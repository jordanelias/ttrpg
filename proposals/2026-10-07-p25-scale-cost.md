# P-25 scale term on Mending Stability — the cost per scale, as the code returns it

## Status: PROPOSED

> **SCOPE.** Reference only (CLAUDE.md §0.05). This document follows the code and is never the reason
> the code is right: if it were deleted the game would behave identically, and if a figure below ever
> differs from what `_resolve_operation` returns, the figure here is wrong and the code is not. It
> creates no plan position, allocates no ID and writes no ledger row. Merging it ratifies nothing
> beyond recording what the code returns.

## 1. What this records

`ED-WR-0010` (consequence 3, `registers/editorial_ledger_wr_archive.jsonl`) ruled that the P-25
"Scale-based Mending Stability" term is authored in code and the document follows. The code is
`systems/threadwork/sim/operations.py`: `COHERENCE_COST_BY_SCALE` and, in `_resolve_operation`, the
branch for `Weaving` and `Pulling` at degree `Partial` or `Failure`. This file states the resulting
cost per scale.

The rule, as the code computes it: let `base = COHERENCE_COST_BY_SCALE.get(scale, 0)`. Then
`mending_stability_delta` is `base` at `Partial` and `base - 1` at `Failure`; at `Success` and
`Overwhelming` it is 0. A scale the table does not name reads as `base = 0`. It is a formula on the
Coherence-cost table, not a second table.

## 2. The figures

Derived by running `_resolve_operation` (with the dice roll replaced by a fixed net-success count so
each degree is reached on purpose, and the Coherence write stubbed out because it is not the quantity
under test), once per scale, for both `Weaving` and `Pulling`. `Ob` is what `attempt_weaving` /
`attempt_pulling` pass: `DEPTH_OB.get(scale, 1)`. The two operations returned identical figures at
every scale.

| scale | `COHERENCE_COST_BY_SCALE` | Ob | MS delta at Partial | MS delta at Failure | MS delta at Success / Overwhelming |
|---|---|---|---|---|---|
| Object | 0 | 1 | 0 | -1 | 0 |
| Personal | 0 | 2 | 0 | -1 | 0 |
| Relational | -1 | 3 | -1 | -2 | 0 |
| Field | -1 | 5 | -1 | -2 | 0 |
| Territorial | -1 | 1 | -1 | -2 | 0 |
| Structural | -2 | 8 | -2 | -3 | 0 |
| Foundational | -2 | 13 | -2 | -3 | 0 |

Facts the table shows and the code produces, none of them a design claim:

- At Object and Personal the Partial cost is 0, so a Partial Weaving or Pulling there moves Mending
  Stability not at all; only Failure costs, by 1.
- Relational, Field and Territorial price Partial -1 and Failure -2, which is also the retired
  degree-only pair; the term moves only the two ends of the scale ladder.
- `Territorial` has a Coherence cost but no `DEPTH_OB` entry, so it resolves at Ob 1.
- `Locking` and `Dissolution` do not read this term. They return a flat -1 at every scale and degree
  (`ms_delta = -1` in `_resolve_operation`), checked here at Structural. `Mending` itself and `Leap`
  return 0.
- The result is reported on `OperationResult.mending_stability_delta` and written nowhere
  (`operations.py`, field comment); no world Mending Stability clock consumes it.

## 3. A choice the code makes, stated as a choice

Pricing Mending Stability off the Coherence-reduction table is a reuse of an already-invented number
as a proxy, as `opposing.py` does and as `operations.py` says in its own comment. The quarantined
threadwork reference holds a steeper five-band ladder (MS -1 to -5) that the code does not use. Which
ladder is right is a question about the game the code answers by running, not one this document
answers.

## 4. How the figures were derived and checked

Command (from the repository root): `python <probe>.py`, where the probe imports
`systems.threadwork.sim.operations`, replaces `operations.roll_pool` with a stub returning a chosen
`net`, replaces `operations.apply_coherence_delta` with a no-op, and for each scale calls
`operations._resolve_operation(op, actor, DEPTH_OB.get(scale, 1), TN_STANDARD,
COHERENCE_COST_BY_SCALE.get(scale, 0), rng=..., scale=scale)` for `Weaving` and `Pulling` across
`net` from 0 upward, recording `mending_stability_delta` against `degree`.

Falsifier: a second script parses the table in section 2 of this file and compares every cell to a
fresh call of the same function. A cell that differs is the finding, and this document is corrected,
never the code.

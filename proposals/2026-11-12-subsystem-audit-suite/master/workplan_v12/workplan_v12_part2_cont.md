## 5. Serial edges and the file census

### 5.1 How the census was made (`census.py`, then `t23.py`)

Every item's `WHERE` lines were parsed for backticked paths (a path under `engine/season/` written short, as `data/fixtures.py`, `rosters.yaml` or part 41's `S/…`, is read as under `engine/season/`); `NEW <path>` and `DELETE <path>` count as edits. **879 files** are named; **269** are edited by items of two or more batches; **610** by one batch only (not listed: a file one batch edits links no two batches). The landing order inside a row is the schedule's (§1.2 of `workplan_v12_part2.md`: step, then the structure's §2.1 order inside a step, then position). **A hot file is one twenty or more items edit**: 42 files (U3 §1.1 counted sixteen by proposals; counted by items the line falls lower, so this list is longer; the hot-file rule of `workplan_v12.md` §7 point 3 applies to every one of them).

**The permanent surface is left out of the serial edges** (`V12_STRUCTURE_part3.md` §7.6: it "links no two batches"; each batch appends once, from its pre-allocated rows): `engine/season/hole_register.yaml` (219 items, 40 batches), `engine/season/requirements.yaml` (46 items, 35 batches), `unified/U1_GLOSSARY.md` (102 items, 32 batches), `references/id_reservations.yaml`, `references/restructure_ledger.md`, `CURRENT.md` and the ED ledgers under `registers/`. **The realm pin file `engine/season/tests/_realm_goldens.py`** (37 items, 37 batches: every mover's `.99`) is left out of §5.2's same-step pairs too: two movers of one step re-pin it in merge order (§3 of part 2), never at once.

**Against U3 §5.1** (122 rows, by file name): every U3 row's file is named by some item except the wildcard row `*.yaml`; **152 of the 259 rows below are not in U3 §5.1** (U3 did not take the nine intake batches' edit sets, and the instruction items and the authors' own reading of their sources add files). The rows the authors and the coverage lane asked for are in the table as generated: B35's six files (`epistemic.py` B09 → … → B35 → B33 → B38 → B39; `decision/budget.py` B03 → B12b → B35; `boot/realm.py`, now nineteen batches; the new host `seam/wrappers/threadwork.py` and `modules/threadwork/`, B35 only, so not below; the geography file `systems/settlements/valoria_geography_v30.yaml` B12a → B12c → B35); the combat files B05 edits (`modules/combat/wrapper.py` B05 → B06 → B14 → B15 → B16 → B18 → B37 → B39; `fight.py`; `combat_systems.py`; `core.py`; `engine/engine_params/combat_engine_v1.json` B05 → B14 → B15 → B16 → B34 → B18); **`harness/play_surface.py` reads B11 → B34 → B20 → B41 → B38 → B39**, which is A42's B34 → B41 → B38 → B39 with two earlier editors the authors did not name (B11.77 and B20.21; B41 now opens at S18, after B20); `tests/test_play_surface.py` B34 → B38, one file, as `master/instructions/IS_CHECK.md` C9 decided (confirmed: B34 creates it, part 25_cont's U6; B38's `IS-B3-GO-04` item adds to it); B21's three files (`loop/sides.py` B21 → B22; `loop/effects_shared.py` B21 → B12a → B21b → … ; `tests/test_march.py` B02 → B17 → B21 → B12a → B21b → …). **One difference from an author's note:** HD-21 says B21b edits `loop/sides.py` after B21; no B21b item's `WHERE` names the file (§11 C-16).

# PESSIMISTIC NERS — the reconciliation logic for the integration stage
# Extends scratchpad/NERS.md. Jordan asked for "pessimistic NERS logic" to RECONCILE the two bodies.

## THE FOUR CRITERIA (Jordan, verbatim intent)
N NECESSARY  cannot be removed without affecting EMERGENCE
E ELEGANT    as distilled as possible WITHOUT AFFECTING FUNCTION
R ROBUST     offers CHOICES WITH REAL IMPACTS FOR THE PLAYER
S SMOOTH     integrates well and PROPAGATES AS REQUIRED ACROSS SCALES

## RULE 1 — E IS A RATIO AGAINST N AND R, NEVER A FOURTH AVERAGED AXIS
An audit that scores four axes and averages them rates an amputated design as elegant. Per object:
state THE EMERGENT POSSIBILITY LOST IF IT IS CUT. An object that cannot name one is surplus.
THE HIGHEST-VALUE FINDING IS A FALSE N-LINE: an object whose claimed lost possibility ACTUALLY
SURVIVES THE CUT because something else already provides it. Three were found earlier this session;
two of the three were still shipping uncorrected weeks later.

## RULE 2 — S IS T5 AND T6 RESTATED
S-UP   can a DEMAND travel up and be filtered BY A NAMED PERSON at a rung?
S-DOWN can an OPPORTUNITY travel down and reach A PERSON WHO HOLDS NO POST?

## RULE 3 — R BINDS AT SEATS A PLAYER CAN OCCUPY. EVERYWHERE ELSE A DOMINANT ACT IS A PORTRAIT.
Established this session by adjudication after the arc work showed that THE TWO ACTS WHICH REPRODUCE
ARC 1 ARE THE TWO ACTS THE GAP REPORT FILED AS DOMINANCE DEFECTS. Jordan's wording is "choices with
real impacts FOR THE PLAYER", so an act dominating an NPC's menu is CHARACTERISATION.
=> Applying R at NPC seats was a category error. Do not repeat it.
=> But this cuts both ways: it makes "IS THIS SEAT PLAYABLE?" a load-bearing question that must be
   answered per seat before R can be applied at all.

## WHAT MAKES THIS PASS *PESSIMISTIC* — five rules for the reconciliation
P-1  ASSUME THE FINDING IS WRONG UNTIL IT SURVIVES A RECOUNT. This session produced: an audit citing
     an object that does not exist; findings recorded as applied that were not; a roster row reported
     null when canon had it; and a falsifier whose statistic grew by construction. Treat every
     inherited number as suspect.
P-2  A CONVERGENCE THAT WAS SEEDED IS NOT A CONVERGENCE. Independent rediscovery is the strongest
     signal available -- and only if the lanes were not told the answer. Where a shared brief asserted
     a conclusion, discount every lane that repeats it.
P-3  A ONE-SIDED SCALE MANUFACTURES ITS OWN RESULT. The arc verdict set had REPRODUCED-BETTER and no
     verdict for "produces this worse". Any tally from that scale is an upper bound, not an estimate.
P-4  PREFER THE INTERPRETATION THAT COSTS THE DESIGN MORE. Where two readings of the evidence are
     available -- "the old machinery was scaffolding" versus "the arcs were load-bearing and the new
     design produces similar-SOUNDING outcomes without the causal structure" -- adopt the second until
     the first is earned by a stated criterion.
P-5  A FIX THAT ADDS A SYSTEM HAS FAILED. The floor fix is the standard to hold others to: three edits,
     two of them DELETIONS, vocabulary SHRINKS. Any proposal that grows the object count must justify
     the growth against an N-line, and "the arcs needed it" is not an N-line unless the story is
     genuinely unreachable otherwise.

## THE TWO PROPOSALS MOST LIKELY TO FAIL THIS PASS, AND THEY MUST BE TESTED HARDEST
 A. A WORLD-SUBSTRATE QUANTITY. Confirmed missing by three routes and defensible as an omission --
    BUT it is a world-state quantity in a design whose code shape forbids stored aggregates and
    container gauges. The offered derivation is "a substrate's condition is the same class as larders
    and harvests, which the design already ticks in the settle phase". TEST THAT DERIVATION. If it
    holds, the object is admissible and the code shape's own ownership table must say so explicitly.
    If it is special pleading, the hole is real and the fix is wrong.
 B. A CONVERGENCE MEASURE. The arcs showed nothing checks whether confrontations arrive at all.
    But the code shape forbids apparatus whose subject is the repository's process rather than the
    game, and CLAUDE.md documents a pathology of answering process failures with apparatus.
    TEST WHETHER A CONVERGENCE MEASURE IS ABOUT THE GAME OR ABOUT THE PROCESS. If the latter, the
    correct output is to state the unmeasured claim and stop.

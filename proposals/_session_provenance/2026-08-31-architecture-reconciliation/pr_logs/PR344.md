### §2 THE PRIMITIVE SET

**§2.1 Four carriers — things that exist:**
```
Person    := (id, weight, marks, capability, stance, ledger, ties)   -- weight defaults to 1
Rung      := (id, kind, stake[], judging_set_rule, dates[], matter, envelope)
Office    := (id, post, rung?, remit, conferral, revocation, establishment, dates[], upkeep)
Site      := (id, rung, kind, condition, drawers[])
```
`Rung` is the name (renamed from `Container`, renamed from `Node` — see §7/§13 naming rows). `Site` IS a carrier — a brief that deleted it is reversed: three limbs fail (a derived accumulator that reads its own previous value is primary state; the draw-weighted mean has no base case; node-keying destroys site identity and produces two wrong verb sets from one collapsed scalar). **The rule, stated once:** `condition` is PRIMARY STATE on the Site an act names; coarser reads are derived and stored nowhere; base case at a Rung with no Sites is undefined and the verb gate doesn't fire. `Rung.envelope` is the demographic envelope; `Rung.matter` holds `stores`, the transmission pointer, and Records. `Office.rung?` optional, null = office-cluster case. `Office` keeps `revocation` (a prior brief silently dropped it); `seat_items` deliberately deleted, unified with `capacity(date)` under D-2.

**§2.2 Identity:** every carrier/edge/Act/Event/Claim/Date/DocketItem/Record carries an `id`, minted from the determinism substream: `id(x) = H(world_seed, tick, subject_id, purpose)`. One mechanism closes two gaps: deterministic+order-independent+unique ids with **no shared allocator** (which would break per-person parallelism), and `purpose` absorbs the missing subject for a `mint` (object doesn't exist yet). Precedent: `engine/substrate/keys.py:145` (`Key.id: str`), uniqueness invariant 1 (`:379-381`), referential integrity invariant 3 (`:384-388`), cycle-freedom by construction (`:389-392`), lookup by id (`:363-365`). **Standing note: DO NOT "fix" ids into pointers** — Godot's `RefCounted` has no cycle collector, and this design's reference graph is cyclic by construction (`succeed ∘ contain` = Rung→Person→Rung is the *normal* case, the heir lives in the hearth); ids break every cycle at the storage layer.

**§2.3 The one edge — `Tenure`:** the record that carries every disputable political fact.
```
Tenure := (id, subject, object, kind, since, until?, conferrer?, degree?, payload?)
   subject   ∈ Person | Rung | Proposition
   object    ∈ Person | Rung | Office | Site | Proposition
   conferrer ∈ Person | Office | null
   kind      ∈ hold | commit | contain | succeed | tie | knot | oblige
```
A Tenure is owned by its subject (one home, one writer, no reach-through — `confer` writes an edge on the subject; the object side is a derived index, never stored). `until?` makes a destroyed tenure a historical fact (feeds `entrenchment = min(1, seasons_held/60)`). `avowed?` deleted (was a boolean over a 3-state domain `avowed·private·covert`, now `commit`'s payload). `payload?` added — carries `knot`'s `depth∈{1,2}` and shared `strain` gauge, `tie`'s `(familiarity, last_contact, channel_class)`.

**The seven kinds** (table, cardinality declared per kind on schema — closes a validation gap single-parent containment needed and never had):
| kind | subject→object | what it is | created by | destroyed by | cardinality |
|---|---|---|---|---|---|
| `hold` | Person→Office | office | `confer` | `revoke` | 1 per Office object |
| `hold` | Person\|Proposition→Site\|Rung | enfeoffment, lordship, **annexation** | `confer` | `revoke` | 1 per object |
| `commit` | Person→Proposition | faction membership at a degree | `commit(+Δ)` | degree→0 | 1 per (subject,object) |
| `contain` | Person→Rung, Rung→Rung | address; containment tree | `admit`,`migrate` | never bare — only re-parenting | 1 per subject |
| `succeed` | Rung→Person | hearth succession pointer | naming act | re-naming | 1 per Rung subject |
| `tie` | Person→Person | ordinary contact | co-presence | decay | 1 per unordered pair |
| `knot` | Person→Person | deep channel | `form_knot` | rupture | 1 per unordered pair |
| `oblige` | Person→Person | kin obligation | kinship,admission,oath | discharge,death,repudiation | 1 per (subject,object) |

`tie`/`knot` stored once, at the endpoint with the lower id (a shared gauge on a directed record otherwise has two homes). `contain` never destroyed by bare `revoke` (would orphan a subtree) — migration/secession are `confer` to a different parent atomically. `annex`/`secede` are DELETED as verbs (zero corpus occurrences); annexation is a `hold` Tenure over a Rung changing hands — "the tree does not move" (Jordan's own ontology, quoted from `REV:618-625,628-629`). `secede` additionally barred: `05:594` ships "secession" for a duke's *defection* (a `commit` moving away) — one word, two shipped meanings, the exact CLAUDE.md §4 failure.

**§2.4 THE PARTITION — one change, three modes, two drivers.** Restructured by a Jordan ruling that replaced an enumeration with a predicate (the earlier "these four, and only these four decider-free channels" enumeration had no membership test and was wrong three ways: matter events licensed with nothing generating one, `wear` unwritable, an authored event deck had no home).

Jordan verbatim: *"Think in terms of state changes. If the state change corresponds to an aspect of human society as limited to the peninsula (polities, institutions, offices, organizations, occupations, religion, settlements, marriage, etc) then it is driven by character choices. If the state change does not correspond to an aspect of human society, like weather or non-peninsular like Altonian Empire or tears in metaphysical substrate, then it is still an event that acts upon the game world."* And: *"A state change, to my mind, includes the creation of a new state or the deletion of a state."*

```
StateChange := (subject, mode, driver, field?, delta?, spec?)
   mode    ∈ mint | alter | efface
   driver  ∈ Act | Event
   subject = the object being changed; IT decides which driver is legal
```
One change primitive, three modes, two drivers, subject picks driver, mode orthogonal to both. The two-driver × three-mode grid (the load-bearing worked table): social-subject/mint = found settlement, establish office, found faction, marry, confer office, take up occupation, found parish; social-subject/alter = move standing/regard/commitment/grievance, amend remit, tend holding; social-subject/efface = dissolve guild, abolish office, strike village from roll, annul marriage, revoke tenure; non-social/mint = new island, river changing course, tear opening, new seam exposed by landslide; non-social/alter = weather, `wear`, body ageing, off-peninsular pressure; non-social/efface = storm destroys harbour, seam worked out, tear closes, body failing. **The bottom-left cell is the new capability: the world can create AND destroy things** (a landslide exposes a seam nobody knew was there; a faction forms around working it; no character decided it should exist).

`read`/`exclude` are NOT modes (re-sited: `reads[]` is a declaration on the Act for the conflict rule; `contests[]` is what `exclude` meant). `Act := (id, actor, verb, changes[], reads[], contests[], payload)`; `Event := (id, kind, subject, changes[], emitted_at)`. Event has no actor; for event-driven mints the substream is `H(world_seed, tick, locus_id, purpose)` where locus is the Rung/Site the event acts on (world root as base case fallback).

**Conflict rule:** two acts conflict iff they share a subject and either **contests** it, or both `alter` an `exclusive` field, or both `mint` states that jointly break a declared cardinality. Ties break on `H(act_id, world_seed)`. **Events never conflict** (not an agent) — events resolve FIRST at their own barrier, acts resolve against the world they leave.

**Commutativity:** `additive` (order-independent: `condition`, `stores`, envelope weights) vs `exclusive` (contested: succession pointer, office's remit, address). Default for undeclared field = `exclusive`. `additive` is order-independent ONLY under batching — clamp doesn't commute with addition at bounds; resolver sums a season's deltas per field and clamps once. ⚠ **AND clamp order is not the only order** — `condition`/`stores` must be FIXED-POINT INTEGERS not floats, because float addition is not associative and a band gate (`verbs(site,c) = {v: condition(c)≥floor(v)}`) turns a one-ulp difference into a verb present in one ordering, absent in another. Cites `CLAUDE.md` §0.1 point 2's own recorded 1-ulp damage-degree-boundary defect as the precedent this repo already paid for.

**`verb` is a name; `changes[]` is the mechanism** — resolver never branches on `verb` or an Event's `kind`. Verb vocabulary is OPEN (practice rank ≥3/≥5 adds verbs); `remit.acts` is NOT the act vocabulary, it's the closed five an office's remit makes eligible somewhere else (issue·determine·confer/revoke·dispatch·convene). MODE set is CLOSED at three.

**Worked case:** can a plague efface a settlement? Plague kills bodies (non-social, event, legal `efface` on Persons). Settlement's deletion is a society aspect (character's choice). So the village empties and STILL LEGALLY EXISTS until an office strikes it from the roll. "Villages do not cease to exist because everyone died. Somebody has to strike them from the roll." Limit: an event may sink a ship/silt a harbour/empty a village of bodies/break a Thread over a province; it may NEVER depose a praefect, dissolve a guild, convert a parish, or move standing/regard/commitment/grievance.

### §3 THE SIGNATURES

**§3.1 The three, and the one change:**
```
choose  : (Person, View, Sensation) -> Act        # NO World, ever
resolve : (Act[], World)            -> Event[]    # NO Person
witness : (Person, Event)           -> Claim[]    # per-person; a collection is a type error
```
Enforcement is by omission. `choose` has no World (not masked, not read-only, not behind an accessor). `resolve` has no Person (no per-actor special case). `witness` takes person first, no signature accepts a collection of persons + one event.

⚠ **§3.1a — the purity guarantee does NOT survive the port as a type-level guarantee**, and this document downgrades rather than repeats the claim. GDScript has no module system/visibility modifiers/scoping; an autoload is a global identifier reachable from ANY script, RefCounted and Resource included; `class_name` statics and `load()`/`preload()` by string are two more doors. So "omniscience is not something an author can write" is FALSE on the port target — and the port's own skeleton proves it: `strike_module.gd:38-39,67` and `combat_engine.gd:60` reach `GameState`/`KeyBus` from inside a resolver module. Same for `witness` — "a consensus broadcast is a type error" is false in GDScript, the collection signature is trivially writable. **The fix:** (1) no live world state behind ANY global name; (2) every resolver-side Query takes an explicit `World` as its FIRST parameter, so calling one from `choose` fails at the call site for want of an argument. Takes enforcement-by-omission from 3 signatures to 23. Downgrade stated plainly: unwritable → unreachable-by-name (human-checkable on one screen of project settings, not compiler-checked).

**`Sensation`** — this document's OWN proposal against a problem the review left open (NOT "the review's fix, corrected" — the review withdrew its needs-as-claims fix with no replacement three times, because minting needs as claims made P2 a second root-token minter and made hunger evictable). ### §4 THE LOOP, IN OUTLINE
```
season(world):
  CALENDAR    barrier·global   writes: dates, dockets              class: calendar
  MATTER      barrier·global   writes: larders,bodies,travel,yield,envelope weights  class: matter
  DELIBERATE  map·per person or cohort·PURE  writes: nothing but the returned Act
  RESOLVE     barrier·global   writes: everything else              class: acts
  WITNESS     barrier·global   fan-out by presence/channel; then per person: witness·decay·eviction  writes: own ledger only  class: interior
```

### §2 CARRIER PLACEMENT (Node/Resource/RefCounted/value)

Four consequences of "nothing is a Node": (1) a Node can reach `get_tree()`/`get_parent()`/the whole scene from any method — the mechanism §3 is about; (2) Node lifetime is frame-scoped (`queue_free()`), `efface` is barrier-scoped (instantaneous cascade in the same resolution step) — cannot be made to agree without a second lifecycle; (3) Node allocation is the heaviest thing Godot offers, and population is the one quantity the design never bounds; (4) the scene tree is a rendering structure — the design's containment ladder is deliberately a Tenure edge not a parent pointer ("a hamlet does not move because a King won a war"); if Container/Rung were a Node and containment were node-parenting, the first `reparent()` anybody writes contradicts the architecture's central ontology.

Full placement table (21 objects): Person→RC one class_name; Cohort→SAME class_name as Person (weight≥1) — "two class_names is the rule broken at declaration" (M-10); Container/Rung→RC under a different name (F-3); Office→RC; Site→RC (condition primary state); Tenure→row in a TenureStore RC (largest object count, cardinality per kind, object-side index derived — one object per edge makes every derivation O(N) scan, §6.4); Act→RC one tick; touch→VALUE (4-field struct-of-arrays inside the Act); spec→value; Claim→row in the owning Person's packed ledger (L=200 per person — one object per claim is N×200 allocations); Event→row in an append-only log (substrate precedent, `keys.py:145,379-392`); Proposition→RC interned by structural equality, never effaced; Record→RC; Date/DocketItem/Petition/Dispensation/ConveningCondition→RC low N; Case/Ground→RC transient per sitting; Venue/door→**Resource+@export+.tres** (authored world data, 12+5 fields — the exact shape `combat_config.gd:11-40` already proves); MatterKind→Resource, authored, never effaced, small generated .tres set; Stores→value, `Dictionary[MatterKind id→int]`, fixed-point; Envelope→value on the Container, `PackedInt32Array`; Sensation→**Vector2** — "the strongest recommendation in the table"; View→value, `PackedInt64Array` of claim ids, must not hold object references; Candidate→value; Query category→`static func` on a namespace class — NOT a type, NOT named `Derived` (M-1,M-2); World→RC, owned by the driver, NEVER an autoload.

**§2.2 `Sensation` as `Vector2`** — the design's own argument gets STRONGER in Godot: `Vector2` is a built-in VALUE type with no fields that can hold a reference, so "it cannot be widened into a masked world" stops being rhetorical and becomes a property of the type the compiler already enforces. "A `class Sensation extends RefCounted` throws this away — the moment Sensation is an object, somebody adds a third field, and nothing at the call site says a rule was crossed."

Findings: **F-3 · FATAL** — the object cannot be named `Container` in Godot on the very ground the design chose the name. `class_name Container` collides with a native Godot type — the `Control`-derived base of `VBoxContainer`/`HBoxContainer`/`GridContainer`; the collision register closed the `Node` row and opened an identical one it didn't check. Fix: rename to `Rung` before the word reaches code (not tested — "no project was opened to confirm the parse error"; the name's occupancy is a fact about the engine's class list in both 4.3 and 4.6, version-independent). M-10 · MAJOR — Person and Cohort must be one class_name. M-14 · MAJOR — `Container.matter` untyped, blocks the whole carrier layer (an untyped GDScript field is a `Variant`, static typing can't reach inside it). m-5 · MINOR — Resource is for tables never a carrier (`load()` returns the cached instance for a path — a `Person.tres` would silently share state). m-8 · MINOR — `Site.drawers[]` stored while `judging_set(c)` is derived, inconsistent. m-3 · MINOR — `Person.address→Path` — `Path` was a Godot 3 class name removed in 4.x; `Address` is the idiomatic word.

### §3 THE PURITY PROBLEM — the question the design stakes itself on, hardest to port

§3.1 the claim: `choose` has "NO World, ever," "not masked, not read-only, not behind an accessor." §14 row 3 "is not a rule the resolver checks; it is a shape the type system makes unwritable."

§3.2 Why FALSE in GDScript — THREE mechanisms, none of which is `Node`: (1) **An autoload is a global identifier, not a Node privilege** — registering `GameState` makes the bare token resolve inside EVERY script, RefCounted/Resource/static function/inner class included. NOT hypothetical: `strike_module.gd:38-39` calls `GameState.get_actor(...)` from inside a resolution module, `:67` writes `GameState.rng.seed`, `:86-90` reads `GameState.new_key_id()`/`GameState.season_index`, `combat_engine.gd:60` calls `KeyBus.emit_key(k)`, `wound_module.gd:40` reaches `GameState.get_actor` again. **"The one module that exists for this port already does, from inside a resolver, exactly what `choose` is forbidden to do."** (2) `class_name` is a flat global namespace — any static func on any registered class is callable from any body. (3) `preload()`/`load()` take a string — `load("res://state/world.tres")` inside `choose` returns the cached live instance, no signature records that it happened. GDScript has no private/module-private/package/friend/import graph/way to scope a name out of a body.

**F-1 · FATAL** — the guarantee AS AN ENFORCEMENT MECHANISM cannot be built in GDScript. "The design is not wrong about what it wants; it is wrong about what carries it." `02:1011-1016` already half-admits it — "nothing enforces it structurally except the absence of a World in choose's signature" — true in Python, none of it in GDScript.

§3.3 What CAN be preserved (nearly as strong): the guarantee moves from the TYPE SYSTEM to the NAME TABLE — "not a downgrade to nothing — a downgrade from unwritable to unreachable-by-name, which is a different, weaker, but genuinely structural property, checkable by a human reading one screen of project settings." THE RULE: no live world state may be reachable by a global name (no autoload holds it, no class_name static holds it, no res:// path resolves to it — the world is a RefCounted constructed by the season driver and passed by parameter, DELIBERATE is the one place it is not passed). AND: every resolver-side Query takes World as its explicit first parameter, every person-side Query takes the asking person and nothing else — calling a resolver-side query from `choose` fails for want of an argument, at the call site, in the reader's face. Worked code example given for `presence`/`judging_set`/`verbs` (resolver-side, unreachable from choose) vs `opening_set`/`leaders` (person-side).

M-2 · MAJOR — the side column is a table when it could be a parameter list — "the highest value-per-character change in the audit." M-13 · MAJOR — the port's EXISTING plan destroys this on day one: `godot/scene_tree_architecture.md:16` makes `GameState` an autoload holding "all tracked state," `STRAT:97` records the live tree's `Meta` autoload as "the single state owner" — both are the exact shape the rule forbids; the port's autoload ruling is still open (a live decision, not fait accompli), and this document supplies the reason it must be decided this way, which was not previously on the table. O-6 · OBSERVATION — `World` is the one type in the design with no record, and it's the type every one of the fourteen refusals is written against; declaring it is the first thing a typed port must do.

§3.4 What does NOT close it: threads don't sandbox (WorkerThreadPool runs GDScript with the same global identifiers); inner classes don't scope (invisible outward only); @tool/@onready/static typing/Callable indirection remove no name; a wrapper hiding the world behind an accessor is explicitly refused by the design itself as `view_of(world,person)` with extra steps (§14 row 2).

### §4 SIGNALS AND FAN-OUT BY PRESENCE

§4.1 Signals belong nowhere in the simulation, and the port ALREADY RULED IT: `STRAT:128` verbatim — "the EventBus carries UI/lifecycle signals only — signals are not Keys (Keys are persisted facts; signals are transient wiring)." No simulation state is ever written by a signal handler.

§4.2 Three independent grounds `witness` must not use signals: SHAPE — `emit_signal` delivers one payload to N receivers, the forbidden §14 row 3 form materialized. PRESENCE-IS-A-COMPUTATION — `reach(e)` changes every season; connect/disconnect traffic proportional to persons×events×seasons is strictly MORE work than the loop it replaces. ORDER — signal invocation order is hidden, synchronous, re-entrant (a handler that emits recurses immediately); the design requires order independence and "the Python substrate carries an explicit re-entrancy meter and a Level-B termination guard for exactly this hazard" — signals give no meter and no cap.

§4.3 The shape that works: two passes matching the design's own split (fan-out global, deposit per person) — worked GDScript code given (`fan_out(w,events)->Dictionary` then per-person `witness(p,event_id)`).

**F-2 · FATAL** — "a consensus broadcast is a type error" is FALSE in GDScript: `func witness_all(ps: Array[Person], e: int)` is as easy to write and type-annotate as the correct form. "What replaces it is weaker and real: witness has exactly ONE call site, in one file, inside the step-2 loop above. A second call site is a diff a reader can see; a second SIGNATURE is not prevented by anything." The design should restate the guarantee as a call-site property. m-7 · MINOR — the design mentions signals nowhere; silence reads as permission; one sentence citing `STRAT:128` closes it.

### §5 CENTRALIZED DATA

§5.1 Four candidate shapes judged: Resource+@export+.tres (right for authored low-cardinality tables like Venue/MatterKind, wrong for per-entity runtime state — `combat_config.gd:11-40` is the correct use, `:5-9` records the defect it fixed, "two scales, one live, one dead, editing the dead one changed nothing"); a data autoload (right for read-only constants, wrong for live world state); generated GDScript const (right for hot scalars read every roll, wrong for anything designer-tunable without a rebuild); engine_params/*.json at load (right as the transport between repos, wrong as the runtime read path — every lookup returns Variant, int64 loses precision).

§5.2 THE RULING: the pipeline has FOUR STAGES, ONE GENERATOR PER STAGE BOUNDARY: code/authored prose → `engine/engine_params/*.json` (exists, behind a blocking --check) → generated `res://data/*.tres` (NEVER hand-authored) → one typed RefCounted holder loaded once, owned by the driver, read by value. "This is not a new recommendation — it is the one the port already made and has not executed." `STRAT:149`: registries "Generated from the ttrpg yaml by the export ritual — never hand-transcribed." Cost of not doing it, measured in this repo's own words: the port's current Key registry answer is "four files, HAND-MADE, covering 4 of 55 types … 93% incomplete before it has even started drifting" (`tools/export_key_types.py:17-19`).

§5.3 What this design specifically owes the pipeline: **M-8 · MAJOR** — the design defines its numeric constants in prose, names no artifact for any of them — partial roster all prose-only: `f(degree)=0·0·1/16·1/8·1/4`, `K=7+Focus+2/Knot-Coherence penalty` and `K=3` per cohort, `stanceweight=clamp(1+(obstinacy/5)·agreement,0.05,2.0)`, `(3+d10)/8.5`, `entrenchment=min(1,seasons_held/60)`, `bandwidth=max(0,2-floor(strain/3))`, `L=200` (marked ASSUMPTION), `Obstacle>2×Pool` refuses the roll, the 5 degree bands. "Under `CLAUDE.md` §0.05 every one of these is reference today and mechanism nowhere, and the documents say so about themselves." m-4 · MINOR — `@export var qual:Dictionary` untyped at the value level (version-gated: typed Dictionary exists later 4.x; fallback: a typed array + const name→index map, which the port already prescribes for conviction vectors). ⚠ Do not lift a number out of `params_tables.yaml` — reiterates `CLAUDE.md` §5's warning that its Degrees-of-Success section holds a pre-ruling ladder.

### §6 THE SEASON LOOP IN ENGINE TERMS

§6.1 NOT `_process`. An explicit driver, headless, on a RefCounted — a season is a discrete transaction with four synchronisation points, `_process` is frame-driven and offers no barrier. The driver is a plain function on a RefCounted callable with no scene tree at all, "already the port's engineering floor" (`STRAT:41,184` "kernel scene-tree-free"). Worked code given (`func season(w:World)->void: calendar(w); matter(w); w.freeze(); var acts:=deliberate_map(w); resolve(w,acts); witness(w,w.events_this_tick); census(w)`). A `Node` appears exactly ONCE in the whole simulation — the outermost layer, to give the driver a callback. If a season exceeds a frame budget, barriers are natural yield points (`await` between steps).

§6.2 Is the parallelism claim realisable? YES, bounded by refcounting not by GDScript. `WorkerThreadPool.add_group_task()` is idiomatic and GDScript genuinely runs on worker threads (no interpreter-wide lock). Binding constraint: EVERY assignment of a RefCounted reference performs an atomic refcount operation — a per-person map walking an object graph of 200 claims/N tenures/a view of object references pays atomic traffic on every hop across every core on shared cache lines. "The speedup is real and it is eaten by refcounting unless the hot per-person data is value-typed" — this is WHY §2's table puts claims/views/touches/Sensation in value types.

§6.3 Three hazards inside the frozen map: **M-3 · MAJOR** — a lazily-built cache inside the map is a data race the purity claim doesn't cover (freezing prevents writes to STATE, not to a memoization cache a resolver-side Derived might build while N threads read it — R-1's "compute-on-demand, never push, never store" is read by most engineers as licensing a cache). Rule stated: **A DERIVED MAY BE CACHED. THE CACHE IS BUILT AT A BARRIER, READ-ONLY UNTIL THE NEXT BARRIER, AND DISCARDED THERE. NOTHING INSIDE A MAP BUILDS ONE.** M-11 · MAJOR — a parallel map must not `append` (`add_group_task`'s completion order is unspecified, producing a nondeterministic act array that inherits into the stratum sort/delta accumulation/conflict graph; fix: pre-size the array, write `acts[i]`). m-6 · MINOR — no Thread-local RNG sharing, no `randomize()`, no `Time` anywhere in the map (see §7).

§6.4 The O(N²) surfaces — where the cliff is, and it is NOT where the design looks (all consequences of "nothing stores an aggregate," which is the right rule — "the cost is the price of the rule and the design does not name it"): de-individuation (N persons × N ledgers × L claims naive, linear with a maintained named-by count); presence/density/footprint (a scan of every commit edge per call, linear with a barrier-built index); judging_set(c) (a scan per call, linear with a barrier-built index); draw_share/share (a scan of a Site's drawers per act, linear with barrier-built denominators); WITNESS fan-out (events×persons if presence is scanned, linear with the presence index); condition(c) coarse read (a tree recursion per call, memoize at the barrier plus a visited-set). **M-4 · MAJOR** — CENSUS's de-individuation predicate as written is QUADRATIC in persons and linear in ledger budget — at L=200, scanning is 200×N² claim comparisons per season; fix is one integer per person incremented/decremented at deposit/eviction time, costs nothing because WITNESS already visits every deposit/eviction. "This is not an optimization; at any interesting N it is the difference between the step running and not running."

§6.5 Order independence and floating point — **THE FOURTH FATAL**. The design's clamp-batching argument is correct as far as it goes, but then claims the STRONGER property, which is false: "additive is order-independent ONLY under batching" (implying WITH batching it IS) and "two attempts resolved in a different order give the same answers" — **IEEE 754 addition is not associative.** The design's own architecture makes the difference observable: `verbs(site,c)={v:condition(c)≥floor(v)}` is a band gate on the summed value, so a one-ulp difference at a floor is a verb present in one ordering, absent in another — and a band-edge closure is an Event people witness. "This repository has already paid for this exact defect class once: `CLAUDE.md` §0.1 point 2 records a 1-ulp aggregate error crossing a damage-degree boundary while its own identity test passed." **F-4 · FATAL.** Two fixes, recommendation is the second: (1) canonical summation order (the five strata + tiebreak hash already exists — gives "reproducible," honest word changes to "canonically ordered" not "order-independent"); (2) **FIXED POINT** — represent `condition` as int in [0,10_000], `stores` in whole units of its MatterKind; integer addition IS associative/commutative, order-independence becomes a FACT not a claim, the band gate becomes exact, the port's own parity protocol gets integer-domain thresholds it already asked for (`STRAT:163`). Worked GDScript given.

§6.6 What the counts can be — the honest answer is the design doesn't say. No population figure anywhere in these documents, in SUP, or in the exported world state (geography IS stated: 16 territories in `engine/engine_params/world_initial_state.json`, "3 duchies→14 provinces→35 settlements"+2 extra-kingdom settlements per `references/propagation_map.md:153`; persons unbounded). Defensible because the design supplies a DIAL not a number (cohort acts once, individuation is demand-driven "nothing generates without a demand," de-individuation returns weight). Load-bearing statement is a SHAPE not a number: population appears LINEARLY in DELIBERATE, QUADRATICALLY in exactly §6.4's five places — "fix those five, and the loop is linear in individuated persons and linear in events; leave them, and the population ceiling is set by CENSUS's scan rather than by anything the designer chose." (No timing taken — an operation count, not a measurement.)

### §7 DETERMINISM

§7.1 The shape: `substream(op)=H(world_seed,tick,subject_id,purpose)` — same hash mints ids, one mechanism closes determinism+parallelism together with no allocator and nothing to serialise on. "This is correct and it is the best structural decision in the design."

§7.2 The Godot implementation: **ONE `RandomNumberGenerator` PER OPERATION, CONSTRUCTED FROM THE SUBSTREAM, USED, AND DISCARDED. NEVER A SHARED INSTANCE RE-SEEDED IN PLACE.** Worked code given (`static func substream(...)->RandomNumberGenerator`). **M-15 · MAJOR** — the skeleton's pattern is the one to ABANDON: `strike_module.gd:67` writes `GameState.rng.seed = key.rng_seed` — a single global RNG object re-seeded per operation — (a) a mutable global (§3's rule forbids it), (b) a data race under any parallel map, (c) a silent coupling (a code path that draws without re-seeding first inherits the previous operation's stream and nothing says so). `:138` then draws from that shared object. "Per-operation instances make the coupling unwritable." **M-6 · MAJOR** — `H` must be an owned, versioned mix, never a built-in — GDScript's `hash()`/`String.hash()` are not specified as stable across engine versions, `Object.hash()` is identity-based — "since the same function mints ids, an engine upgrade that changes the hash renames every object in every save." Write the mix explicitly (64-bit FNV-1a or SplitMix64 over UTF-8 bytes), version it. Two GDScript-specific traps: `int` is signed int64 and `>>` is arithmetic shift (unsigned right-shift must be masked); `RandomNumberGenerator.seed` is a uint64 property (passing a negative int is correct, `abs()`ing it throws away a bit and changes the stream).

§7.3 The checklist of what breaks order independence in practice (7 items, each mapped to a Godot landing site): shared RNG (`strike_module.gd:67`, existing precedent); two draws sharing a purpose within one (subject,tick) (m-1 · MINOR — widen the purpose-uniqueness rule to per-draw not merely per mint slot); collecting map results by append (M-11); float summation order (F-4); Dictionary iteration feeding a draw or sum (Dictionary is insertion-ordered in GDScript, insertion order is a function of act order — "sort keys at every serialization and every accumulation point," which `STRAT:167` already names as one of two semantics that "corrupt silently"); hash()/String.hash()/randomize()/Time (M-6); a lazily-built index (M-3).

§7.4 Cross-language parity — bit-parity between the Python oracle and GDScript is NOT a goal and should not become one (`STRAT:159` rules it, `:161-164` supplies the replacement: named draws, recorded-draw replay, key-log equality, integer-domain assertions). "the design's `(3+d10)/8.5` magnitude reading and its N d10 pool reading are both integer-then-divide, which is exactly the shape that survives; nothing in the design requires a Gaussian" — "the new design is EASIER to port for parity than the shipped combat engine is."

### §9 SAVE/LOAD AND SERIALIZATION

§9.1 What serializes vs doesn't (table): the four carriers, every Tenure (incl. until-stamped historical), every ledger claim, Propositions/Records/Dates/DocketItems/Petitions/Dispensations/ConveningConditions, Site.condition/Stores/Envelope counts, world_seed+tick — DOES serialize. Every row of the Derived catalogue, Sensation/View/Candidate, Act/touch, any barrier-scoped index, Person.address/Person.ties (both VIEWS of Tenures — writing them is a second update path) — does NOT.

§9.2 Do derived ids survive a round trip? YES, and the trap is a MISREADING not a mechanism — STORE THE ID, DO NOT STORE A COUNTER, NEVER RECOMPUTE AN ID AT LOAD (a tick and purpose aren't recoverable later). "The design is right and consistent here. The failure mode is a reader concluding 'derived ⇒ not serialized' and reconstructing ids at load, which renames every object in the save."

§9.3 The Godot mechanics and the silent corruption: **M-5 · MAJOR** — `.tres` is the wrong save format, three reasons: (a) embeds script paths, breaks when a script moves; (b) `ResourceLoader` INSTANTIATES scripts — a save file becomes an execution surface the moment it's shared/edited; (c) the resource cache returns the same instance for a path — reload-after-save can hand back the pre-save object. Fix: `FileAccess` + an explicit serializer. **M-6b · MAJOR** (same root as M-6) — 64-bit ids through Godot's JSON lose precision SILENTLY (`JSON.parse_string` produces doubles; integers above 2^53 don't round-trip; the corruption appears only for ids in the top ~99.9% of the space and manifests as a dangling reference three loads later). Fix: ids cross the boundary as hex String, or the save is binary. **M-12 · MAJOR** — the design and the port's governing spec carry TWO DIFFERENT save models, neither cites the other: this design reads as "a full-state snapshot, no log to replay" ("replay is a re-run, not a log"); `STRAT:19` says "save state=initial conditions+Key log; replay=deterministic re-execution," `STRAT:164` makes key-log equality "the master parity check." These are INCOMPATIBLE load paths (initial-conditions-plus-log means loading a season-200 save re-simulates 200 seasons). Recommended ruling (costs nothing to state): the save IS a state snapshot; the event log is retained for fiction/UI/witness provenance but never the load path; re-run-from-seed stays a TESTING device. **O-1 · OBSERVATION** — the design is already right about ids-not-pointers, for a Godot reason it didn't know it had: Godot has NO GARBAGE COLLECTOR, RefCounted is pure reference counting, a reference cycle is a PERMANENT LEAK; because every reference in the design is an id not a pointer, "a faithful port leaks nothing."

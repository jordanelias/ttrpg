## 2. governance_ripple_substrate_v1.md -- mechanism reproduction

**Status (line 5):** `PROPOSED (2026-07-11) . Lane: IN (cross-cutting) . Author-pass, not yet Jordan-ratified`. Not ratified -- but it is itself an integration spec over things that ARE ratified/canonical (Key substrate, settlement_layer, faction_politics).

**Core loop (1, lines 30-74).** A single closed causal loop, ASCII-diagrammed lines 35-66:
`EVENT fires (deck draw, Pi-gated)` -> `hits SETTLEMENT OPERATION (typed levers)` -> `RESPONSE BURDEN (3 pressure vectors, 3)` -> `RESPONSE shaped by GOVERNANCE MODE (which verbs, at what cost, gated by power_base)` -> `OUTCOME emits a Key that updates STANDING (advance/demote)` -> ripples fan out into `FI leads / SC-Parliament / FA windows` (6) -> `AGGREGATES across scale: settlement->territory->faction->peninsula` (7) -> `seeds/advances an EMERGENT ARC` (8), which re-weights the deck, closing the loop.

**2 Settlement levers (lines 78-110).** Existing stats reused (Prosperity 0-5, Order 0-5, Defense 0-5, Legitimacy 0-7, Popular Support 0-7, Weight, FacilityTier 0-3, Treasury, Pi 0-10). New levers only pass a "different decision shape" test (line 87-88). Five levers table (lines 93-99): **StockLevel** (buffer institution), **Assessment tag** (`assessed_base`, locked figure), **Capital-Posture** (Mobile/Fixed), **Consent-Rule** (Unanimity/Majority), **route/corridor Precedent**. Open ruling R-1 (still open per this doc; not found resolved elsewhere in this pass).

**3 Response burden -- three pressure vectors (lines 114-137).** Table: **Upward** (governed pushing up -- reads Local-Actor Disposition/Needs/Pi/Petitions, resolves via Hold Court/Sponsor/Treat), **Downward** (superiors demanding -- reads the Directive/patron ledger, resolves via Comply/Bargain/Petition), **Positional** (the seat's own cost -- reads AP scarcity + the roster docket's `power_base`-typed vulnerability). Positional is named "this session's genuinely new contribution" (line 127) -- `power_base` (patronage/merit/kinship/bureaucratic/military/purchased/ideological) determines which levers are affordable.

**4 Event generation (lines 141-155).** Already-canon per `governance_play_redesign_v1.md` 2.1-2.3: Pi-gated draw (low->Opportunity/Ambition; mid->Petition/Friction/Intrigue; high->Crisis), trigger-predicate-filtered, tag-weighted. One substrate requirement: every card resolution must emit a Key.

**5 The event->standing bridge (lines 158-270), the design lead's own primitive.** `resolution_quality(Key) = w_d*(delivered_to_Directive - demanded_by_Directive) + w_n*(delivered_to_Need - demanded_by_Need)` (lines 184-189) -- a **computed field on the emitted Key**, not a new stat, projected onto the Key's existing `impact_vector` (2.4/2.5 of `key_substrate_v30.md` axes). 5.5 (lines 213-263) is a fully worked example (Kronmark famine, Governor Aldric) tracing one event through all 8 loop arcs. Open ruling R-2 (NPC-contests-player-seat) -- still open.

**6 The ripples (lines 273-316).** Three consumers of the same Key: **6.1 FI** -- negative resolution Key raises the concealment inventory `Investigate` draws from (WIRED, CHN-3 precedent). **6.2 SC/Parliament** -- flagged `AT-RISK` (see 13 below) -- the contract has NO input hook reading an external Key into contest stakes; the spec **catches itself** proposing a dependency canon doesn't have. **6.3 FA** -- routes through the EXISTING Mandate aggregation (`Mandate = Sum settlement L/PS`), not a new "Key aggregate" -- graded WIRED via Mandate.

**7 Cross-scale aggregation (lines 319-360).** Four scales already on every Key (`scale_signature`): INDIVIDUAL -> SETTLEMENT (Mandate = Sum L/PS, CANON; Treasury = Sum Prosperity x10, CANON) -> **TERRITORY (the genuine unbuilt scale -- R-3, still open)** -> FACTION -> PENINSULA (Cooling flag / peninsular strain). Bidirectional, already true in canon per this doc.

**8 Arc feedback (lines 364-375).** Resolved chains re-weight the deck via the existing `weight: base + Pi-scaling + tag-modifiers` machinery; the arc generator reads the Key log, doesn't need an authored plot.

**9 The primitive discipline (lines 379-398) -- five primitives, nothing else counts as real:** (1) **Key emission**, (2) **Ledger tag** (Precedent/Grudge/Debt/Reputation/Compact), (3) **Disposition**, (4) **Pi**, (5) **Standing/consolidation_progress**. **13 Self-audit (lines 458-490)** -- the spec grades its own edges against its 9 test: 5/8 **WIRED** today (event->settlement, settlement->Mandate->faction, cross-scale stamping, FI ripple, and -- per 13's table -- the spine), 2 **HOOK-NEEDED** (event->standing needs one authored 1.0a trigger clause; arc-feedback needs one tag-modifier-write convention; FA window needs reframing onto Mandate, not a new aggregate), and exactly 1 **AT-RISK** (event->Parliament/SC, 6.2) -- flagged as the one place the spec itself "caught itself reaching for a resemblance instead of a dependency."

### Which parts of the proposed design does this already own?

- **The single Event/StateChange channel.** 9's five primitives + 1's causal spine ARE, functionally, the proposal's `StateChange := (subject, mode, driver)` + `Query` + the six-loop-step idea -- except expressed as "everything is a Key emission + a read of Key/Ledger/Disposition/Pi/Standing," already CANONICAL at the Key-substrate layer (see 2 of this report) and PROPOSED (not yet ratified) at this ripple-substrate layer.
- **`Act[]/Event[]` resolve semantics.** 14.1's table (`domain_actions` owning module, `d_sigma`/`dice_pool` resolvers, `IN: player choice -> OUT: da_outcome.*`) is a working `resolve : (Act[], World) -> Event[]` shape, name-for-name close to the proposal's second signature, already wired through `module_contracts.yaml`.
- **`witness`.** 6.1's FI ripple ("negative resolution Key raises concealment inventory") is a witness-shaped mechanism (an event becomes discoverable content for a *different* actor's later action) but is NOT `witness : (Person, Event) -> Claim[]` per-person -- it's a shared inventory mutation, closer to `resolve` output than to a per-actor perception function.
- **Ambition engine / mint-alter-efface parallel.** 8's arc-feedback and the ambition engine (cross-referenced, defined fully in `governance_play_redesign_v1.md` 3, see 3 below) are the closest existing analog to the design's Act-driven `mint`/`alter`/`efface` on human-society subjects -- an NPC's autonomous choice creates/changes standing-bearing state.
- **What the proposal RE-INVENTS relative to this doc:** the proposal's abstraction is more general (four carriers, one edge type, one state-change triple) where this doc is domain-specific (settlement governance only) -- but the *primitive discipline itself* ("only a read/write dependency is real, never a thematic resemblance," 9) is the SAME governing idea the proposal's `Query`/`StateChange` doctrine re-derives from scratch, unattributed. The proposal does not cite this document (per PR #344's finding) despite this being, in its own words, "the event deck's own governing spec."

## 3. governance_play_redesign_v1.md -- mechanism reproduction

**Status (line 3):** `PROPOSAL -- drafted 2026-06-22. Extends/replaces settlement_layer_v30 3.2`.

**Part 0 -- Five pillars (lines 9-18):** P1 governing = choosing under constraint (bounded AP + political side-effect, no free stat-pumps); P2 settlement = pressure-driven scene engine; P3 NPCs have ambitions, act autonomously; P4 the **two-stroke churn** (world->player / player->world alternate and condition each other); P5 the world **remembers** (Precedent/Grudge/Debt/Reputation tags).

**Part 1 -- The Governor's Turn.**
- 1.1 Action economy: `AP = 2 + FacilityTier_s` (2-5/season), three ordered layers per season: Directive (mandatory) -> Governance Phase (spend AP on verbs) -> Personal Phase.
- 1.1a Clerk Capacity (lines 33-41): a SECOND opaque AP source, `Retain Clerks` verb, +1 effective AP/CC point, silently increments a hidden Clerk Corruption counter -- discoverable only via Investigate.
- 1.3 The governance verbs table (lines 51-61): **Develop, Fortify, Keep Order, Hold Court, Sponsor, Treat, Levy, Investigate** -- each with AP cost, roll, effect, tradeoff (which faction gains power), and **Churns** (the world-delta emitted, explicitly P4/P5). Deliberately NOT orthogonal stat-pumps -- each verb forces a "method" choice that hands power to a different faction.
- 1.3a Locked Extraction Figures (lines 73-83): **Assessment tag** (`assessed_base`) + two acquisition triggers -- **Survey** (unilateral, 2 AP roll) and **Encabezamiento/Negotiate Quota** (negotiated, converts variable Levy into a fixed multi-season **Compact**, a 5th Ledger tag family).
- 1.3b Bind the Cells (lines 85-93): Goningumi collective-liability mechanic -- new `Keep Order` method, **Collective Liability** Ledger tag (Grudge-family variant), 3 stacked tags auto-seed a Crisis card.
- 1.3c Ordenanza Ratification (lines 95-109): RATIFIED sub-branch of Hold Court (guild self-regulation vs civic check) -- Ratify/Reject/Amend.
- 1.4 The Directive (lines 111-125): mandatory faction order each season; typed (Extract/Tax/Suppress/Install/Host/Cede); responses **Comply/Bargain/Defy-Divert** each with up-tier and down-tier effects; suspicion accrual -> Recall scene or faction-emergence seed.
- 1.5 Settlement Needs (lines 127-129): independently emitted from state, routinely conflict with the Directive -- the vise.
- 1.6 The Ledger of Consequence (lines 131-142): 5 durable per-settlement tag families -- **Precedent, Grudge, Debt, Reputation, Compact**. Survive succession.

**Part 2 -- The Event Deck (lines 144-206).** 2.1 Pressure model: `Pi_next = clamp(Pi + Sum_unserved_Needs + Sum_active_Grudges + Sum_NPC_ambitions_in_motion + external_shock - Sum_player_releases, 0, 10)` -- bands: low(0-2) Opportunity/Ambition, mid(3-7) dramatic (Petition/Friction/Intrigue), high(8-10) Crisis. 2.2 the full card YAML schema (id/family/triggers/weight/cooldown/excludes/the_ask/responses/follow_on). 2.3 seven card families table (Petition/Friction/Opportunity/Crisis/Intrigue/Ambition/Thread). 2.4 drawing: `1 + floor(Pi/3)` cards/season, filtered/weighted/deduped.

**Part 3 -- NPC specification (lines 209-264).** 3.1 the NPC dossier YAML schema: `identity, convictions, ambition{goal, method, timeline, progress}, ethic, loyalty, leverage{wants, fears, secret}, relationships(Knots), trajectory{if blocked, if Disposition<-2, if Conviction violated}`. 3.2 the ambition engine: every significant NPC advances `progress` each Accounting tick regardless of player action; hitting threshold emits an Ambition card. 3.3 speccing for maximum friction (orthogonal Convictions, overlapping ambitions, cross-cutting Knots, ethic spread). 3.4 a full worked dossier example (Hedda Vorn).

**Part 4 -- The churn engine (lines 268-297).** 4.1 the guarantee: world always acts (mandatory Directive + `>=1` card draw), player always acts (every verb emits a world-delta). 4.2/4.3 the two strokes defined precisely. 4.4 a full two-season worked example closing the loop. 4.5 homeostasis via the Pi clamp.

**Part 5 -- Integration (lines 300-326).** 5.1 explicit hooks into existing canon (Convictions/Disposition/social-contest/Domain-Actions/Accounting reused directly; Knots = the NPC relationships graph; alpha/beta ethic; L/PS->Mandate). 5.2 build sequence gated on settlement registry existing (closed -- see `sim/registry.py`, 5 below). 5.3 open balance questions.

**Part 6 -- Summary (lines 329-337).** The player-facing restatement of the whole loop.

### Which parts does the proposal already own vs re-invent

- **The NPC ambition/trajectory schema (Part 3) is the design's closest pre-existing analog to autonomous `Act`-driving-`StateChange` for non-player `Person`s** -- an NPC has convictions (won't compromise), an ambition (goal/method/timeline/progress), and a trajectory (re-plans when thwarted) that advances **every tick whether or not the player engages**. This is materially more complete than anything in `proposals/2026-08-31-ideal-v2/` for "how does a non-player Person choose."
- **The Ledger of Consequence (5 tag families) is a working, ratified-adjacent implementation of exactly the kind of "durable record of what an Act/Event did" the design's `StateChange` log gestures at** -- with a concrete taxonomy (Precedent/Grudge/Debt/Reputation/Compact) the proposal's more abstract `mint|alter|efface` triple does not supply.
- **The verb table (1.3) IS `choose : (Person, View, Sensation) -> Act`** for the specific case of a settlement governor -- every verb already declares its AP cost, its roll (resolver), its effect, and critically its POLITICAL cost (which faction it empowers) -- richer than the proposal's bare signature.
- **Genuinely NOT owned here:** the proposal's cross-domain generality (Person/Rung/Office/Site as universal carriers regardless of subsystem) has no equivalent -- this doc is settlement-governance-specific; its NPC/ambition schema, verb menu, and Ledger tags are NOT phrased as instances of four universal carrier types anywhere in this document.

## 4. holonic_container_doctrine_v1.md and _architecture/ -- containment doctrine vs. the design's "Rung as edge, not parent pointer"

**Status:** CANONICAL -- ratified 2026-07-02 (PR #55, ED-1083/ED-1094).

**The doctrine's containment model (line 18-26):** *"Valoria is a bottom-up emergent game over a nested container/wrapper architecture: holonic -- each container is at once a whole and a part -- with **one uniform canonical shape at every scale**, events propagating **up** (aggregated at each boundary crossing) and **down** (distributed/refined)."* The cross-map (line 39) states: *"**Holonic scale ladder** | `sim/` subpackages: `personal -> thread -> provincial -> territory -> peninsular -> world`, with `cross_scale/` as the boundary layer."* This is a **fixed, top-imposed ladder of scale tiers**, not a graph of edges between arbitrary holon instances -- the doctrine's own words: *"structure is uniform and top-imposed (one shape at every scale)"* (line 24).

This DISAGREES in kind with the design's claim (per CONTEXT) that "the containment ladder is an EDGE, not a parent pointer": the holonic doctrine's containment is a **compile-time-fixed tier sequence** (one canonical scale ladder the whole engine shares), enforced by `module_contracts.yaml`'s uniform Key IN -> resolver -> OUT shape and `ci_module_shape_check.py`. It is a structural/architectural containment claim about CODE MODULES (which package a given mechanic lives in), not a per-instance relational claim about GAME ENTITIES (which settlement is inside which territory, which office reports to which office).

**The instance-level containment claim** -- closer to what the design actually means by "Rung" -- is answered differently in two places that partially DISAGREE with each other:
1. `systems/settlements/scale_hierarchy_v1.md` 1 (RATIFIED, 2026-07-13): Country > Duchy > Province > Territory > Settlement is presented as a literal nested tree -- *"People in one place comprise settlements comprise territories comprise provinces comprise duchies comprise country"* (line 11) -- with Province explicitly **existence-conditional, not a fixed parent pointer**: *"a province is an emergent aggregation that exists only while its constituent territories share a common faction holder... when that condition stops holding, the province simply stops existing as a unit"* (2, lines 33-36). This IS structurally close to "containment as a computed/derived relation," at least for the Province tier -- though Settlement->Territory and Territory-under-Province still read as fixed geographic parent pointers.
2. The same document's 5.1 (lines 81-93) states factions explicitly do NOT follow parent-pointer containment: *"Factions do not necessarily need to hold territory -- they need to hold PEOPLE... A local faction is not automatically a subsidiary of whatever provincial faction sits above it geographically... territory-holding is a consequence of holding enough people in enough places, not the base unit of power itself."* This is the closest existing canon comes to the design's "containment is an edge, computed from Tenure, not a parent pointer" -- but it is scoped to faction membership, not to the general Person/Office/Site/Rung containment claim the proposal makes universal.

**Verdict:** the geography ladder (Settlement/Territory/Duchy/Country) is fixed-tree containment; the Province tier and faction "holding" are both **already-ratified precedent for edge/derived containment** -- meaning the design's "Rung as edge" claim is NOT novel, it is a generalization of a distinction `scale_hierarchy_v1.md` already draws case-by-case (fixed for geography, derived/holds-people for faction, existence-conditional for Province) without naming a single unifying primitive the way the proposal's `Rung` does.

**Other _architecture/ docs relevant to containment:** `governance_type_registry_v1.md` 2.1 (lines 60-71) catalogs the governance-type cascade, consent-gate, faction power-basis, independence-eligibility, and cross-scale claiming as separate FLAG/VECTOR-typed entries rather than a unified edge type -- direct evidence the corpus has NOT yet unified these into one `Tenure`-shaped primitive, which is exactly the gap the design's `Tenure` (7 kinds) claims to close. `governance_consolidation_v1.md` and `ners_vsg_reconciliation_v1.md` record the ratification history (D1-D6, B12) behind `scale_hierarchy_v1.md`.

## 8. GAPS -- what the proposal needs that systems/ has NOT designed

- **No unified `Tenure` edge type.** Governor-of-settlement (`governor_id` FK), faction-holds-people (5.1 prose only), Compact (Ledger tag), Treaty (`TreatyRecord`), and rank-holding (`faction_politics_v30.md` Standing) are FIVE separately-shaped mechanisms for "who holds what, under what terms." Nothing in `systems/` proposes collapsing them to one edge type with 7 kinds.
- **No universal 4-carrier abstraction (Person/Rung/Office/Site).** Every mechanism above is subsystem-scoped; there is no design doc proposing that a "cohort" is literally "a Person at weight > 1," for instance.
- **No literal `mint`/`alter`/`efface` verb vocabulary**, and critically no explicit statement of Jordan's Partition (human-society subjects change only by Act, everything else by Event) anywhere found in `systems/` -- this is a genuine design decision the proposal introduces that has no precedent found in this lane. (Caveat: `governance_type_registry_v1.md` 1's FLAG/VECTOR split and `scale_hierarchy_v1.md`'s Province-existence-conditionality are ADJACENT but do not state this partition.)
- **The Territory scale is explicitly an open architectural gap** (`governance_ripple_substrate_v1.md` R-3, still open) -- relevant because the design's `Rung` claim would need to resolve exactly this gap to be implementable.
- **Six-step loop granularity has no precedent.** The live/CANON loop is 3 phases (SEASON_TICK/ACTION/ACCOUNTING_BOUNDARY, owned by `engine_clock.py` per ED-IN-0199). Nothing in `systems/` proposes splitting MATTER, DELIBERATE, WITNESS, CENSUS as distinct phases -- CENSUS in particular (a periodic recount) has no clear existing analog; ACCOUNTING_BOUNDARY does aggregate stats but is not described as a census of carriers.

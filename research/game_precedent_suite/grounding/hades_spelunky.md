## What is established

| # | claim | tag |
|---|---|---|
| 1 | Spelunky (the original): "The level is made of 16 rooms in a 4x4 grid", with four basic room types defined by which exits they are **guaranteed** to have (type 0: "a side room that is not on the solution path"; 1: left and right; 2: left, right and bottom; 3: left, right and top). | [V3 KAZ 2026-11-12] |
| 2 | **The path is built first, by construction.** A start room is placed in the top row; each step draws 1 to 5 (1-2 move left, 3-4 move right, 5 move down; at an edge the path drops); when the path goes down, "the generator overrides the current room to be type 2 (which always has a bottom drop)", and the room below must be type 2 or 3; trying to drop from the bottom row places the exit. | [V3 KAZ] |
| 3 | Then "we add some random type 0 rooms to every grid space that is not on the solution path. These rooms don't have any guarantees of exits on ANY side, which is why you sometimes see them walled off." | [V3 KAZ] |
| 4 | Wikipedia agrees on the shape only: "Levels are randomly generated"; terrain is destructible, which the designer found "made the level progression more lenient as players could create their own paths instead of using the path generated by the level". | [V3 WP-SP 2026-11-12] |
| 5 | Hades: a run goes through "several rooms drawn from a pool of pre-determined layouts, with the order they appear in and the enemies that appear being randomized". | [V3 WP-HD 2026-11-12] |
| 6 | Hades' narrative is selected from run state: the game "peeks at the moments players encounter mid run, like encountering a character while Zagreus' health is below a certain threshold, and feeds one of several possible pre-written events to players based on that situation"; "the development team can weight certain events in a way that gives them more of a chance to pop up". | [V3 GD-HD 2026-11-12] |
| 7 | Supergiant chose the roguelike structure so that branching stories would be seen over many runs. | [V3 WP-HD] |

## What this note does NOT establish

- **"Reject or repair a level with no path" for Spelunky.** Not supported. KAZ describes the opposite method:
  a guaranteed path is constructed first and the rest is filled in around it; no level is tested and rejected.
- A **priority** ordering of Hades' dialogue. `?`. What is sourced is selection by situation and weighting
  (row 6). A search result notes that the selection internals are not publicly documented [S3].
- "Reward and encounter budgets" in either game: not found in the sources read. `?`.
- Anything about Spelunky HD or Spelunky 2 (KAZ is the original freeware game).
- Any number beyond those quoted in rows 1 and 2, which describe one version read by a third party.

## Bearing on the suite (a correction)

`21_PROCEDURAL_GENERATION.md:112` and its convergence 4 at `:149` ("Constraints plus rejection keep a generated
world coherent ... Hades/Spelunky `[M]`") should not list Spelunky as an instance of rejection: it is an
instance of **constraint by construction** (the solvable path is laid first). The convergence itself is
carried by its other sources (Compton, Togelius, the FW Q6 ruling); Spelunky supports a different and
cheaper method for the same end, which is nearer to that audit's own "solvability precondition at
generation".

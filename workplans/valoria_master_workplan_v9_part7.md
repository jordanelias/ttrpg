## 0. How an entry here reads

Every entry carries the same fields: `STATE`, `LANE`, `BATCH` (a batch id of `_part3` §B, `B-A`…`B-Z`; a position that lands in two batches names both; `B-Z` is the held-or-LEAVE set, which is not a session), `R` (the THE NINE rows it moves, or `—`), `WHAT`, `DEPS` (kinds D data, F file collision, I instrument, J Jordan-gated, R ordering by ruling) and `EDITS`, `EXIT` (the narrowest command or measure that observes the failure), `FALSIFIER` (the test that would show the entry wrong, and what it must observe), `SOURCE` (each cite opened when this was written). No entry lacks an exit instrument or a falsifier. `STATE` is `B` (buildable), `BLK:<ids>`, `J:<id>` (Jordan's; the ten held rulings the plan's recommendation answers read `ANSWERED [medium; Jordan to correct] (RS-21 n)` in the entry that builds them, each with its revert, "Jordan states the other option"), `ask-then:<id>` (attached to a position; off the queue) or `LEAVE` (named, unscheduled; no R-row moves on it). Handles are `MB-nn`, `PC-nn`, `WR-nn`, `GO-nn`, `FA-nn`; a surviving v8 number is the ALIAS. `valoria_master_workplan_v9.md` §3 is the state index; this file holds each entry listed there as `_part7`. A figure is never stated without the command that re-derives it and the date it was read; a carried v8 block is verbatim apart from the edits its own note names.
